# openapi-qoder

从 Torna（toena）接口文档生成高质量 TypeScript 类型 + 请求函数的工具。

两段式流水线：**Stage-1 确定性代码生成** → **Stage-2 AI 类型重构与语义润色**（Qoder Agent SDK）。
通过 AST 契约校验、命名账本和已验证产物缓存，保证多次运行可复现、可增量且不漂移。

产物对标 `battery-asset-management-web`，但解决其两大痛点：类型冗余、分页类型不可复用。

---

## 环境要求

- Node.js ≥ 18（本仓库用 24 测试）
- 依赖已随仓库声明，安装即可：

```bash
npm install
```

## 鉴权

| 用途 | 变量 | 说明 |
| --- | --- | --- |
| 拉取 Torna 文档 | `TORNA_TOKEN` | Torna 请求头里的 `token` 值（见 `接口/*.ts`） |
| Torna 地址（可选） | `TORNA_BASE_URL` | 默认 `https://doc-dev.qijiswap.com` |
| Stage-2 AI 润色 | `QODER_PERSONAL_ACCESS_TOKEN` | 未设置时回退到本地 `qodercli login` 登录态 |

```bash
export TORNA_TOKEN="xxx:eyJhbGci..."
# 可选：export QODER_PERSONAL_ACCESS_TOKEN="qoder_..."
```

## 快速开始

```bash
# 1) 列出所有空间 / 项目，拿到 projectId
npx tsx src/cli.ts list

# 2) 生成某个项目（Stage-1 确定性 + 复用已有账本 Stage-1.5）
npx tsx src/cli.ts gen <projectId>

# 3) AI 润色（类型复用/extends + 语义命名 + 数组推断 + 契约/tsc 校验）
npx tsx src/polish-run.ts <projectId>

# 4) 记录 AI 决策和已验证产物，并纳入 git（下次可精确复用）
npx tsx src/cli.ts harvest <projectId>
git add .openapi-qoder/naming.lock.json .openapi-qoder/polished && git commit -m "chore: update polish cache"
```

或交互式选择空间 → 项目 → 直接生成：

```bash
npx tsx src/cli.ts pick
```

产物在 `generated/<projectId>/`（Stage-1）与 `generated/<projectId>-polished/`（最终）。
`generated/` 已被 gitignore；需提交 `.openapi-qoder/naming.lock.json`，发生结构优化时还需提交 `.openapi-qoder/polished/` 下的已验证快照。

## CLI 命令

| 命令 | 作用 |
| --- | --- |
| `list` | 列出空间 / 项目 |
| `pick` | 交互式：空间 → 项目 → 生成 |
| `gen <projectId>` | 拉取接口 + Stage-1 生成 + 精确重放已验证的 Stage-2 结果 |
| `harvest <projectId>` | 校验 Stage-2 结果并记录命名决策与结构化产物快照 |
| `status <projectId>` | 查看：已入账本 / 结构变更需重润色 / 未解析 `unknown[]` 数 |

Stage-2 润色单独运行：

```bash
npx tsx src/polish-run.ts <projectId>
# 可调参数：
POLISH_BATCH=4 POLISH_MAX_TURNS=60 npx tsx src/polish-run.ts <projectId>
```

npm scripts 快捷方式：`npm run qgen -- <命令>`、`npm run polish -- <projectId>`。

## 产物长什么样

每个选中目录生成一个文件（可包含多个接口），文件内包含类型与请求函数：

```ts
// AUTO-GENERATED by openapi-qoder (Stage-1 codegen + Stage-2 AI polish).
// Type contract validated; decisions are cached under .openapi-qoder/.
import request from '@/utils/request';
import type { PageResult } from './common.js';

export interface VehicleFilterBaseParam { /* 查询与导出的公共字段 */ }
export interface HostingVehicleQueryParam extends VehicleFilterBaseParam { /* 查询专属字段 */ }
export interface HostingVehicleExportParam extends VehicleFilterBaseParam { /* 导出专属字段 */ }
export interface HostingVehicleVO { /* ... */ }
export type HostingVehiclePageData = PageResult<HostingVehicleVO>;

/** 托管运营车辆分页列表 */
export const getHostingVehiclePage = (data: HostingVehicleQueryParam) =>
  request.post<HostingVehiclePageData, HostingVehicleQueryParam>('/v1.0/hostingVehicle/page', data);
```

枚举会被提炼为常量 + 联合类型（`common.ts` 提供公共 `PageResult<T>`）：

```ts
export const USER_TYPE = {
  /** 个人 */ PERSONAL: 'CUSTOMER_TYPE_C',
  /** 公司 */ COMPANY: 'CUSTOMER_TYPE_B',
} as const;
export type UserType = typeof USER_TYPE[keyof typeof USER_TYPE];
```

要点：
- 响应壳（`code/msg/traceId/...`）被剥离，只保留 `data`。
- 分页结构自动识别为公共 `PageResult<T>`。
- Stage-2 会按业务语义抽取公共接口，并通过 `extends`、`Pick`/`Omit` 或别名复用类型。
- 请求 URL 去掉网关前缀 `/2m /2b /2c`（代理会自动补）。
- `@/utils/request` 为默认请求模块，可在生成选项中替换。

## 润色账本与缓存（可重入的关键）

`.openapi-qoder/naming.lock.json` 以 Torna `docId` 为稳定 key，保留兼容旧版本的命名/字段类型决策，并记录结构化润色快照：

```jsonc
{
  "version": 1,
  "apis": {
    "nzDyBg12": {
      "shape": "ebd35438c83b",
      "types": { "HostingVehiclePageItem": "HostingVehicleVO" },
      "fns": {
        "nzDyBg12": {
          "mechanical": "hostingVehiclePage",
          "semantic": "getHostingVehiclePage",
          "locked": true
        }
      },
      "fieldTypes": { "HostingVehiclePageParam.operatorNames": "string[]" },
      "polishArtifact": {
        "baseHash": "7c8d...",
        "contentHash": "0e91...",
        "file": "nzDyBg12-7c8d....ts"
      },
      "source": "ai"
    }
  }
}
```

完整快照保存在 `.openapi-qoder/polished/`，并通过内容哈希校验。再次运行时：
- 原始 Stage-1 内容完全一致 → 精确恢复上次通过校验的 Stage-2 文件，**不调用 AI**。
- Torna 文档或生成配置发生变化 → 不直接套用旧快照；将上一版类型设计作为精简参考交给 AI，在新 Stage-1 上增量润色，尽量保留仍有效的命名与抽象。
- 没有账本记录的 Stage-2 文件不会被生成命令覆盖，避免未入账结果丢失。
- `source: "manual"` 的条目不会被自动 harvest 覆盖。

典型工作流：

```
gen → polish-run → harvest → 提交 naming.lock.json 与 polished/
# 再次 gen：未变化文件精确重放；变化文件基于上一版设计继续 polish
```

## 校验

```bash
npm run check:src        # 工具源码类型检查
npm run check:out        # 校验 generated/ 产物可编译
npm run check:polished   # 校验 Stage-2 润色结果可编译
```

Stage-2 有两道校验门：先用 TypeScript AST 展开 `extends`、别名、泛型及 `Pick`/`Omit`，确认每个请求的字段、可选性、只读性、入参/出参结构和运行时代码未变化；再执行 `tsc`。任一步失败都会回滚该文件。
